# 具身/3D 算子优化实录（Voxelization + BEV Lift-Splat）

> 用 KernelAgent 闭环（本机 deepseek-v4-pro + 云端 RTX 2080 Ti）优化两个具身/3D 感知算子，
> 选型依据 `docs/世界模型热点算子调研报告.md` §4.3/§4.4。
> 写于 2026-07-24。

---

## 一、选型

从调研报告 §4 具身/3D 蓝海里，按 KernelAgent 闭环适配性（单 kernel + 有 eager baseline + 单卡可验证 + memory-bound 融合空间）筛出两个：

- **点云 Voxelization**（§4.3）：N 点 → [256,256,8] voxel 网格均值池化。LiDAR 预处理。优化空间 = fused hash+pool，减少原子竞争。
- **BEV Lift-Splat**（§4.4）：6 相机 feat × depth → scatter-add 到 BEV。优化空间 = fused 不物化外积（B·C·H·W·D 巨张量）。

## 三、关键发现

### 发现 1（最重要）：thinking budget 是推理模型的解药

**症状**：deepseek-v4-pro 对复杂算子 prompt 大概率"全程思考、不产出最终代码"（`_extract_text` 拿到 `len=0` 的纯 thinking 响应）。RMSNorm 简单能成功，voxelization 复杂就卡。

**根因**：推理模型的 thinking 会吃光 `max_tokens` 预算，最终 text 答案没空间产出。

**解药**：金山云网关支持 Anthropic 的 `thinking` 参数，**限制 `budget_tokens`**（让思考别太长，给答案留空间）。实测 `budget=4096` 让 voxelization prompt 稳定产出闭合可运行代码。

**关键认知**：这与"effort 调 max"**相反**——max 让思考更长、答案更可能被挤掉；调小 budget 才是正解。

**已固化**：`AnthropicProvider.get_response` 支持 `ANTHROPIC_THINKING_BUDGET` env（不设时向后兼容）。见 `utils/providers/anthropic_provider.py`。

### 发现 2：Triton 表达力边界（BEV 难突破的根因）

BEV 的"深度维 D 循环 + 每个 d 一个标量线性地址 scatter"，Triton **不支持向量索引 `lin[i]`**（`unsupported tensor index: constexpr[0]`）。LLM 反复踩：`lin[i]`、`wgt[i]`、`d_mask[i]` 全不行——必须逐 d 全标量算。

这导致 BEV 的 baseline（逐 (b,h,w) 程序 + 逐 d 标量 atomic）已是该结构在 Triton 下的接近天花板实现。要更快需更聪明的 tiling（多 (h,w) 共享坐标），但表达受限。

**结论**：KernelAgent 优化受**底座模型能力 + Triton 表达力**双重约束。结构友好的（voxelization 点→voxel 单映射）能优化；结构需要 Triton 难表达操作的（BEV 的 D 维向量 scatter）难突破。

### 发现 3：闭环对失败正确丢弃

多轮里 LLM 产出 `continue`（JIT 不支持）、`_semantic`（内部 API）、`tl.static_shared`（不存在）、缺逗号等错误代码，**全部被云端 verify 客观拒绝，best 不被污染**。这是 KernelAgent 相对直接用 LLM 的核心价值实锤。

## 四、踩坑（Triton JIT 语法，LLM 反复踩，已加进 prompt 约束）

- `t[:, i]` 2D 列切片不支持 → 用 1D load
- `lin[i]` / `wgt[i]` 向量用 constexpr 索引不支持 → 标量逐个算
- `.clamp` 不存在 → `tl.maximum/tl.minimum`
- `continue`/`break` 在 @triton.jit 内不支持 → 用 mask
- `tl.static_shared`/`tl.shared`/`_semantic` 不存在 → 用寄存器 + `tl.atomic_add`
- `tl.arange`/`tl.static_range` 的参数必须 constexpr

这些已写进 `examples/optimize_kernel_remote.py` 的 OPT_PROMPT 约束段，降低 LLM 失败率。

## 六、复现

```bash
# 1. 部署 daemon（见 docs/远程GPU部署.md，--python-bin ka_gpu）
# 2. 跑优化（必须设 thinking budget）
env -u ALL_PROXY -u all_proxy \
  OPENAI_MODEL=deepseek-v4-pro ANTHROPIC_THINKING_BUDGET=4096 \
  ~/miniconda3/envs/kernel_agent/bin/python examples/optimize_kernel_remote.py \
    --kernel-dir examples/optimize_voxelization \
    --url http://127.0.0.1:8765 --token <token> --rounds 3
```

**注意**：复杂算子必须设 `ANTHROPIC_THINKING_BUDGET`（4096 量级），否则推理模型大概率不产出代码。

## 七、下一步

- BEV 的 D 维 scatter 受 Triton 表达力限制——可尝试改算子结构（如把 D 维展平成 1D 序列用 1D scatter 规避向量索引），再优化。
- 换更强的代码底座模型（gpt-5/Claude）可能突破 BEV——当前 deepseek-v4-pro 代码质量不够。
- 更多算子：按调研报告选 Sandwich-LN+AdaLN（CogVideoX，LN 融合易）、3D-RoPE（elementwise，同 RMSNorm 易成功）。
