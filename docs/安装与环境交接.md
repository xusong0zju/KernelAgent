## 二、安装过程与关键决策（怎么装的）

### 1. 建环境
```bash
~/miniconda3/bin/conda create -n kernel_agent python=3.11 -y
```
- 选 Python 3.11：官方要求 `>=3.10,<3.13`，3.11 最稳
- condarc 已配清华镜像（conda-forge），但建环境时默认源仍偏慢，耐心等

### 2. 装 PyTorch —— 走清华源（关键决策）
**第一次走 pytorch.org 卡住**（国内慢），换成清华 pip 镜像后顺利：
```bash
~/miniconda3/envs/kernel_agent/bin/pip install \
  --proxy http://127.0.0.1:13363 \
  -i https://pypi.tuna.tsinghua.edu.cn/simple \
  torch
```
- 装的是 **torch 2.13.0+cu130**（带 CUDA 绑定版，pip 默认就是这版）
- 本机无 GPU → `torch.cuda.is_available()` 返回 False（预期）
- **triton 3.7.1 作为 torch 依赖一起装上了**，省单独一步

### 3. 装 KernelAgent 本体
```bash
cd ~/PreResearch_WS/KernelAgent
~/miniconda3/envs/kernel_agent/bin/pip install \
  --proxy http://127.0.0.1:13363 \
  -i https://pypi.tuna.tsinghua.edu.cn/simple \
  -e .
```
- editable 模式（`-e`），改代码即时生效
- 把 pyproject.toml 的依赖（openai/anthropic/gradio/omegaconf 等）全装上

### 关键决策回顾

**Q：torch 用国内源？**
A：用清华源 `pypi.tuna.tsinghua.edu.cn/simple`。pytorch.org 国内太慢，清华源快。也可用 `mirror.sjtu.edu.cn/pytorch-wheels/`。

**Q：GPU 版 torch 要等云端 GPU 机器？**
A：对。当前本机无可用 GPU（驱动 11040 太老 + 无 GPU 设备），装 GPU torch 也用不上。策略：
- **本机**：当前 CPU 模式（cuda: False），能 import/跑测试框架/做 shape 推理，**agent 大脑不需 GPU**
- **云端 GPU 机器**：等开发好 ssh 后，**在云端装匹配驱动/CUDA 的 torch**，本机执行层改远程调用

## 三、踩到的坑（务必注意）

### 坑 1：`ALL_PROXY=socks://...` 导致 gradio import 失败
**现象**：`import gradio` 或跑 `kernel-agent`/`pipeline-ui` 等 UI 入口时报错：
```
ValueError: Unknown scheme for proxy URL URL('socks://127.0.0.1:18190/')
```
**根因**：你环境里有 `ALL_PROXY=socks://127.0.0.1:18190/`（和 `all_proxy` 小写），httpx 默认不支持 socks scheme。
**这不是安装问题**，是环境变量问题。

**解决**（任选一）：
```bash
# 临时清掉（只对当前终端）
unset ALL_PROXY all_proxy

# 或装 socks 支持
pip install "httpx[socks]"

# 或在跑 UI 前临时清
env -u ALL_PROXY -u all_proxy python scripts/triton_ui.py
```
**只影响 UI 入口**（gradio），不影响核心 agent（Python API / `Fuser.pipeline` CLI 不经 gradio）。

### 坑 2：conda create 偶尔卡住
conda 解析默认 channel 在国内偶尔慢/卡。已配清华镜像（`~/.condarc`），但首次建环境仍可能等几分钟。若长期卡住，考虑用 `conda create --offline` 或直接用 base 的 python 建 venv。

### 坑 3：pip 走代理
装包必须带 `--proxy http://127.0.0.1:13363`（你提供的本地代理）。代理偶尔偏慢（15s 级），大包如 torch 要耐心等。

### 坑 4：torch CUDA 驱动警告
import torch 时可能弹：
```
UserWarning: CUDA initialization: The NVIDIA driver on your system is too old (found version 11040)
```
**预期**，本机驱动旧 + 无 GPU。不影响 import 和 CPU 推理。等云端机器用匹配的 CUDA 版。

## 四、预判：本机无 GPU + 远程云 GPU 怎么用（核心）

KernelAgent 当前架构**假设 GPU 在本地**——所有 GPU 操作（编译 Triton / 跑测试 / NCU profiling / benchmark）都是本地子进程，**无 ssh/remote 抽象**（grep 全 repo 无 paramiko/fabric/ssh/REMOTE_GPU）。

### 要改的 3 个执行点（agent 大脑零改动）
| 执行点 | 代码位置 | 当前 | 改造 |
|---|---|---|---|
| 测试执行 | `triton_kernel_agent/worker_util.py` `_run_test_multiprocess` | 本地 `spawn` 子进程 | 远程执行 |
| NCU profiling | `kernel_perf_agent/kernel_opt/profiler/ncu_profiler.py` | 本地 `ncu` 二进制（硬编码 `/usr/local/cuda/bin/ncu`） | 云机跑，CSV 回传 |
| benchmark | `triton_kernel_agent/platform/nvidia.py` + benchmarking | `torch.cuda.Event` 本地 | 云机执行 |

### 不用改的（agent 大脑，纯网络）
- LLM 调用（provider 抽象，HTTP）
- prompt 模板（Jinja）
- 子图分解 / AST 分析（纯 Python）
- worker 编排逻辑（管理子进程的决策，不亲自执行）
- NCU 指标 → prompt 格式化（`metrics_to_prompt`，纯字符串）

### 推荐改造路线：远程 daemon（路线 B）
1. 在云 GPU 机起常驻服务（FastAPI/简单 socket），暴露 `run_test(code)` / `profile_ncu(kernel)` / `benchmark(kernel)` 三个接口
2. KernelAgent 的 3 个执行点改成 HTTP 调远程 daemon
3. daemon 内部用 subprocess 跑（复用现有 `compare_and_bench` / `run_ncu.py` / `_run_test` 逻辑）

**优点**：常驻省进程开销、文件传输 daemon 管、可多客户端复用、NCU/benchmark 结果结构化回传。
**改动集中**：只动 3 个执行点，agent 大脑零改动。

### 要注意的坑（远程化时）
1. **NCU 需权限**：`KERNELAGENT_NCU_USE_SUDO` 环境变量，云机 daemon 要有权限跑 ncu（或配 sudoers）
2. **文件同步**：生成的 kernel/测试代码要传云机；云机要装好匹配的 Triton/PyTorch/CUDA
3. **路径**：`ncu_profiler.py` 硬编码 `/usr/local/cuda/bin/ncu`，云机路径可能不同，用 `ncu_bin` 参数传入
4. **spawn 语义**：daemon 进程不要 fork 已初始化 CUDA 的状态
5. **延迟**：LLM 多轮迭代 + 每轮远程执行，单 kernel 生成时间会拉长（本地几十秒 → 远程可能分钟级）
6. **并发**：本地 4 worker 并行是 4 个本地子进程，远程要 daemon 支持并发或开 4 ssh，云 GPU 显存/算力要够

详见前序调研报告第十七节（KernelAgent vs KernelGen）+ 本 session 的"远程 GPU 部署分析"。

## 六、接国产模型（deepseek-v4-pro / glm-5.2）

### 两个模型都真实存在（已核实官方文档，2026-07）
- **DeepSeek-V4-Pro**：官方 API 文档 `api-docs.deepseek.com` 列明 `deepseek-v4-pro`、`deepseek-v4-flash`；`deepseek-chat`/`deepseek-reasoner` 将于 2026/07/24 弃用
- **GLM-5.2**：智谱 `docs.bigmodel.cn` 列明 `glm-5.2`（最新旗舰，1M 上下文，Coding 开源 SOTA）、`glm-5.1`、`glm-5`、`glm-5-turbo`

### 两者都是 OpenAI 兼容 API
| 模型 | base_url | OpenAI 兼容 |
|---|---|---|
| DeepSeek-V4-Pro | `https://api.deepseek.com` | ✅（还支持 Anthropic 兼容 `https://api.deepseek.com/anthropic`） |
| GLM-5.2 | `https://open.bigmodel.cn/api/paas/v4`（确切字符串需查 `docs.bigmodel.cn/cn/guide/models/text/glm-5.2`） | ✅ |

### 接入路径 A（最简单，推荐）
KernelAgent 的 `OpenAICompatibleProvider` 支持 `base_url`（`utils/providers/openai_base.py`）：
```python
class OpenAICompatibleProvider(BaseProvider):
    def __init__(self, api_key_env: str, base_url: str | None = None):
        if self.base_url:
            self.client = OpenAI(api_key=api_key, base_url=self.base_url)
```

**步骤**：
1. 在 `utils/providers/available_models.py` 注册表加：
```python
ModelConfig(name="deepseek-v4-pro", provider_classes=[OpenAIProvider],
           description="DeepSeek V4 Pro"),
ModelConfig(name="glm-5.2", provider_classes=[OpenAIProvider],
           description="智谱 GLM-5.2"),
```
2. 让 `OpenAIProvider` 读 `OPENAI_BASE_URL` 环境变量
3. 配 `.env`：
```
OPENAI_API_KEY=<你的 DeepSeek 或智谱 key>
OPENAI_BASE_URL=https://api.deepseek.com   # 或 https://open.bigmodel.cn/api/paas/v4
OPENAI_MODEL=deepseek-v4-pro               # 或 glm-5.2
```

### DeepSeek 的 Anthropic 兼容端点（更省事，待验证）
DeepSeek 提供 `https://api.deepseek.com/anthropic`（Anthropic 兼容）。KernelAgent 默认 provider 是 Anthropic，若 `anthropic_provider.py` 支持 `ANTHROPIC_BASE_URL`，则：
```
ANTHROPIC_API_KEY=<DeepSeek key>
ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic
OPENAI_MODEL=deepseek-v4-pro
```
**需先核实** `utils/providers/anthropic_provider.py` 是否支持自定义 base_url（读源码确认）。

### 注意坑
1. **reasoning_effort 特殊处理**：`openai_base.py` 对 `gpt-5/o3/o4` 系有 reasoning 特殊分支，换 DeepSeek/GLM 时不生效（DeepSeek-R1 推理是内置的，不靠该参数）——不影响能用，但高级推理优化不生效
2. **生成质量**：KernelAgent 默认 Claude-sonnet-4/gpt-5（顶级代码模型），国产模型代码能力不错但可能略逊，复杂 Triton kernel 生成质量可能下降。建议 DeepSeek-V4-Pro（若推理强）做生成阶段
3. **API 限流**：高频多轮（4 worker × 10 轮）可能限流，配重试/降频
4. **prompt 是英文**：建议输入描述也用英文（prompt 模板英文）
5. **成本**：国产 API 比 Claude/GPT 便宜很多，优势
