## 四、当前能力与局限

### 能做（已验证）
- 本机配金山云 deepseek-v4-pro 生成 kernel 代码 ✅
- 一条命令全自动部署云端 GPU daemon（含建隧道）✅
- 远程 GPU 真跑 test/benchmark，结果结构化回传 ✅
- 本机 LLM refine + 远程 GPU 验证的闭环 ✅（bug kernel → 自动修对）
- benchmark-driven 算子优化（真实计时选 best）✅（RMSNorm +55%）

### 局限
- **NCU profiling 在 2080Ti 没全跑通**：`--launch-skip` 对低 launch 次数 kernel 全跳过；2080Ti 不在 gpu_specs 表。当前优化是 benchmark-driven 非 NCU-driven。修法：调 launch-skip / 加 2080Ti 到 `kernel_perf_agent/kernel_opt/diagnose_prompt/gpu_specs.py`。
- **daemon 单进程串行**：单卡正确（GPU 要串行），多卡并发待加。
- **隧道生命周期**：deploy 进程退出隧道可能断，长跑改 `ssh -fN` 或 systemd。
- **GLM-5.2 未接**：智谱是 OpenAI 兼容，要新建 `OpenAICompatibleProvider` 子类。
- **批量接口收益近零**：单卡串行下 batch 不省延迟（瓶颈是 subprocess torch import，不是 HTTP 往返）。真要省得做持久 benchmark 子进程。

## 五、下次怎么接着干

### 要重新用云端 GPU
1. 云端机开机（凭据在 `docs/远程GPU部署.md` 或你的记录里）
2. 部署：
   ```bash
   env -u ALL_PROXY -u all_proxy ~/miniconda3/envs/kernel_agent/bin/python \
     -m triton_kernel_agent.remote.deploy \
     --ssh-host <host> --ssh-port <port> --ssh-user root --ssh-pass <pass> \
     --repo /home/xusong/PreResearch_WS/KernelAgent \
     --port 8765 --python-bin /root/miniconda3/envs/ka_gpu/bin/python
   ```
   （ka_gpu 是云端 py3.11 环境，**必须指定**，否则 triton 3.3/py3.12 ABI 崩——见部署文档坑1）
3. 跑：`docs/RMSNorm优化实录.md` 第六节

### 下一步候选方向（按性价比排）
1. **修 NCU 驱动**：加 2080Ti 到 gpu_specs + 调 launch-skip，让优化从 benchmark-driven 升级到 NCU-driven（瓶颈分析驱动）。这是 KernelAgent 真正的杀手锏，当前没用上。
2. **跑更多算子**：复制 `optimize_qwen_rmsnorm/` 优化别的千问算子（attention/MLP/rotary embedding），积累优化数据。
3. **接 GLM-5.2**：多 LLM 路由（beam_search_diverse 的 models 列表）。
4. **持久 benchmark 子进程**：省每个 kernel ~3.5s torch import，单卡下也能显著降延迟。
