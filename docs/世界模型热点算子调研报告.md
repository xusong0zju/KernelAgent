## 〇、一句话结论

| 领域 | 算子成熟度 | 手写优化空间 | 建议 |
|---|---|---|---|

## 二、视频世界模型 / 视频扩散算子

> 视频世界模型（Sora 类、HunyuanVideo、Wan、CogVideoX）的核心是 **DiT（Diffusion Transformer）+ 3D 时空注意力**。最大的计算黑洞是注意力本身。

### 2.1 【实时核实】3D 时空注意力（视频扩散的 85% 瓶颈）

- **出现位置**：所有视频 DiT 每个 block 的 self-attention。输入形状 `[B, T, H, W, C]`（或 patchify 后 `[B, T·h·w, C]`）。
- **复杂度**：全注意力 O((T·h·w)²)。**5 秒 720P 视频，attention 占 800/945 秒总推理时间（~85%）**【实时核实，arxiv 2502.04507】。compute-bound。
- **为何难优化**：token 数随 T×H×W 爆炸，720P 5s ≈ 数百万 token；3D 局部性强但全注意力忽略之；flash-attention-3 是闭源 CUDA 极致，Triton 难超 70-80%。
- **主流实现**：FlashAttention-2/3、SageAttention、xformers。
- **优化空间**：见 2.2 STA（结构化稀疏）、2.3 SageAttention（低比特）。**结论：不要死磕全注意力 FA-3，要往稀疏化/低比特走。**

### 2.2 【实时核实】Sliding Tile Attention (STA) / SSTA —— 视频扩散注意力最新方向

- **算子**：Sliding Tile Attention，tile-by-tile 的 3D 局部滑动窗口注意力（非 token-wise SWA），硬件感知。
- **来源**：arxiv 2502.04507（FastVideo / hao-ai-lab，开源 https://github.com/hao-ai-lab/FastVideo）。**HunyuanVideo 1.5（arxiv 2511.18870，2025-11）的 SSTA = Selective Sliding Tile Attention**，是其核心架构创新，8.3B 参数消费级 GPU 可推理。
- **性能**【实时核实】：比 FA2 **2.8-17x**，比 FA3 **1.6-10x**，MFU 58.79%。HunyuanVideo 上无训练 945s→685s，微调后 268s（VBench 仅降 0.09%）。
- **为何重要/优化空间**：这是 2025 视频扩散最热的算子方向，仍在快速演进；基于"视频注意力分数集中在局部 3D 窗口"的观察，把全注意力冗余消除；开源、kernel 级优化空间大（不同 tile 形状、stride、selective 策略、与 3D-RoPE 融合）。
- **Triton 可行性**：**高**——2D/3D 滑动窗口 + 分块 softmax，是 Triton 擅长的 fused attention 模式；论文已给开源参照实现。
- **给 KernelAgent 的机会**：在 STA/SSTA 基础上做更优 tile 调度、与 SageAttention 低比特融合、与 3D-RoPE 融合、反向 fused——这些都是明确的、有 SOTA 参照的手写空间。

### 2.3 【实时核实】SageAttention（INT8/FP8/FP4 量化注意力）

- **算子**：分块量化注意力。QK^T 用 INT8（INT32 累加），PV 用 FP16 累加器；SageAttention3 用 Blackwell **FP4 Tensor Core**。
- **来源**：github thu-ml/SageAttention（清华陈键飞团队）。
  - SageAttention（arxiv 2410.02367，ICLR 2025）：INT8 + FP16 累加。
  - SageAttention2（2411.10958，ICML 2025）：outlier smoothing（K=K-mean(K)）+ per-thread INT4。
  - SageAttention2++（2505.21136）：更高速度同精度。
  - **SageAttention3（2505.11594，NeurIPS 2025 Spotlight）**：FP4，RTX5090 上 **1038 TOPS，比最快 FA 快 5x**；**首次把低比特 attention 用于训练**（8-bit fwd+bwd）。
- **实测集成**【实时核实】：CogVideoX 端到端 **+35%**；Wan2.2 单独 -5.8~6.2%，组合 P2P+Cache-DiT 最高 **-47%**；HunyuanVideo 有官方 example。即插即用（三行替换 `F.scaled_dot_product_attention`）。
- **硬件**：Ampere/Ada/Hopper/Blackwell，INT8+FP8+FP4。
- **优化空间**：SageAttention 已是 SOTA 量化注意力，但 **与 STA/SSTA 的融合（低比特 + 稀疏滑动窗口）** 是空白；FP4 训练的 attention 还在早期探索。Triton 端的量化-softmax-累加融合仍有调优空间。
- **给 KernelAgent 的机会**：复现/优化 SageAttention 的 Triton kernel（其 kernel 是 Triton/CUDA 混合），或做 "SageAttention + STA" 融合 kernel。

### 2.4 【综述】3D VAE / Causal VAE（causal Conv3d + GroupNorm+SiLU 融合 + 时空反卷积）

- **出现位置**：视频扩散 encoder/decoder，把视频压到 latent 再还原。HunyuanVideo/Wan/CogVideoX/Open-Sora/LTX-Video 的 causal 3D VAE（时间 4×、空间 8× 压缩）。每个 ResnetBlock：Conv3d → GroupNorm → SiLU → Conv3d。
- **复杂度**：Conv3d compute-bound（解码 720p 单层数十 GFLOP）+ GroupNorm memory-bound 混合；解码器上采样中间激活 `[B,128,33,90,160]` 多份并存，峰值 GB 级。
- **为何难优化**：**causal 卷积要求时间维只看过去帧，标准 cuDNN Conv3d 不直接支持，需手动 pad+mask，破坏 cuDNN 最优路径**；GroupNorm+SiLU+Conv 三段不融合则每段一次 HBM 读写；反卷积（transposed Conv3d）上采样是 cuDNN 弱项 + causal pad 冗余；shape 动态致 cuDNN autotune 缓存命中率低。
- **优化空间**：**GroupNorm+SiLU+Conv3d 三段融合 Triton kernel**（高价值，解码器瓶颈）；**causal Conv3d 专属 kernel**（滑动窗+时间维循环，避开 cuDNN pad 冗余）；**causal transposed Conv3d 专属 kernel**（cuDNN 反卷积弱项）；Upsample+Conv3d 融合。**无成熟开源 Triton causal-Conv3d + GroupNorm 融合实现**。
- **Triton 可行性**：中-高——3D 卷积 tiling 比二维复杂，但 causal 约束让 cuDNN 失效反而使专属 kernel 收益确定；解码是推理最后一步，用户感知延迟最直接，单卡可验证。

### 2.5 【综述】Patchify / Unpatchify（3D reshape+transpose 巨大显存）

- **出现位置**：DiT 输入端把 `[B,T,H,W,C]` patchify 成 token 序列 `[B, T·(H/p)·(W/p), C·p³]`，输出端 unpatchify 还原。
- **复杂度**：纯 reshape+transpose，**memory-bound，显存峰值巨大**（中间张量是输入的 C·p³ 倍）。
- **为何难优化**：transpose 导致非连续访问，朴素 PyTorch 实现会物化巨大中间张量。
- **优化空间**：fused patchify（不物化中间，逐 patch 写出）、与位置编码融合。
- **Triton 可行性**：高——纯 memory 重排，Triton fused gather/scatter 是教科书场景。

### 2.6 【综述】3D-RoPE + attention 融合（视频 DiT 最高价值融合空白）

- **出现位置**：HunyuanVideo（head_dim 按 T/H/W 三段分频）、Wan、CogVideoX 的注意力 Q/K。
- **复杂度**：elementwise + 频率表预计算，memory-bound；访存量与 Q/K 同量级。
- **为何难优化**：当前多数官方实现（HunyuanVideo/Wan 仓库）是 **eager 两 kernel**（gather freqs + rotate_half + mul），中间物化 `x_rotated` 副本显存翻倍；3D 频率分段与 FA3 tiling 不天然兼容，"在 kernel 内做 RoPE"融合复杂；长视频外推需 NTK/YaRN 式可变 base frequency。
- **优化空间**：**融合进 attention kernel（Q/K load 后原地旋转再喂 GEMM）**，消除中间物化 + 省一次 HBM 往返——所有视频 DiT 必用、当前**无成熟开源 Triton 3D-RoPE 融合 kernel**，是明确高价值空白。频率表预计算 + cache。
- **Triton 可行性**：高——elementwise，Liger 已有 1D RoPE 开源参照，3D 是直接扩展；单卡可验证，baseline 是 eager RoPE + FA2。

### 2.7 【综述】CogVideoX Expert Transformer / Sandwich-LN + AdaLN 调制融合

- **出现位置**：CogVideoX（智谱）Expert Transformer（文本/视频 expert 交替 + 门控融合，替代 cross-attention）+ Sandwich LayerNorm（每子层前后各一层 LN）+ AdaLN（timestep 调制）。
- **复杂度**：**每 block 4 次 LayerNorm**（sandwich = pre+post 各 2 子层），memory-bound；expert 门控 fusion 是 elementwise mul+add。
- **优化空间**：**Sandwich-LN + AdaLN 调制融合**（pre-LN + scale-shift + post-LN 一个 kernel，省 3-4 次 HBM 往返）；expert gated FFN 融合（gate+up GEMM+mul+down GEMM，可迁移 SwiGLU fused）。LN 融合本身成熟，但 Sandwich+AdaLN 组合无现成实现。
- **Triton 可行性**：高——LN 融合是 Triton 教科书场景，实现门槛低，适合作为快速胜利。

### 2.8 【综述+实时核实】视频扩散的新算子与新加速工作（2025-2026）

- **Wan2.2 双专家 MoE**【综述】：业界首个视频 MoE（27B 总参/14B 激活），双专家按 SNR 路由（高噪声专家负责整体布局、低噪声专家负责细节），GEMM 只激活一半。优化点：timestep-aware SNR 路由融合进 gating kernel、expert grouped GEMM 避免 gather/scatter。可借 vLLM/Megatron 语言 MoE 路径迁移。
- **6Bit-Diffusion**【综述，arXiv:2603.18742，清华+复旦+上交】：CogVideoX-2B/5B 上速度 **1.92×**、内存 **3.32×**。核心：动态 NVFP4/INT8 混合精度 + **TDC（时间增量缓存）** 跳过相似步 + **PDR（误差净化）**。是视频扩散低精度的前沿工作。
- **FP8/FP4 per-timestep 动态 scale**【综述】：视频扩散特有难点——不同 timestep 激活范围差异几个量级，单一 scale 会溢出/截断，需 per-timestep/per-block 动态 scale + autotune。FA3 FP8 不带 timestep scale，是空白。FA3 FP8 attention + 3D-RoPE 融合也无现成。
- **TurboDiffusion**【综述+实时核实，清华 TSAIL + 生数 + UCB】：组合加速框架，单 RTX 5090 实测 **Wan2.1-1.3B-480P 184s→1.9s（97×）、Wan2.1-14B-720P 4767s→24s（199×）**。核心 = SageAttention + SLA（稀疏线性注意力）+ rCM（时间步蒸馏）+ 模型量化。属系统级组合优化，非单算子。
- **Flow Matching ODE 步间缓存复用**【综述】：相邻 timestep 中间激活相似度高，复用跳过部分 block 计算。TurboDiffusion 的 TDC 即此思路。偏 scheduler/cache 系统层，与 KernelAgent"单算子 kernel 优化"定位稍有错位，但端到端收益最大。
- **4DGS 可微光栅化（视频高斯）**【综述】：高斯带时间轨迹，光栅化需插值时间维，kernel 更复杂——4D 世界模型刚需。与 §4.1 3DGS 同源，4DGS 是其视频时序扩展。

## 三、LLM 世界模型 / 长上下文 serving 算子

> LLM 作为"语言世界模型"，推理 serving 的核心是 prefill（compute-bound）vs decode（memory-bound）两阶段。**这一领域已被 FlashInfer/FA-3/vLLM/SGLang/TensorRT-LLM 高度吃透，手写空间小**【实时核实 FlashInfer README】。

### 3.1 【实时核实】FlashInfer —— LLM serving 算子的"成熟度天花板"

FlashInfer（github flashinfer-ai/flashinfer）已原生支持以下算子，**意味着这些算子手写优化空间已被工业级库吃透**：

| 类别 | 已支持的算子 |
|---|---|
| Attention | Paged/Ragged KV、Decode/Prefill/Append、**MLA（DeepSeek 原生）**、Cascade（共享前缀层级 KV）、Sparse（block-sparse/variable）、**POD-attention（fused prefill+decode 混合 batch）** |
| GEMM | BF16、FP8（per-tensor/groupwise）、**FP4（NVFP4+MXFP4, Blackwell）**、Grouped GEMM（LoRA/多专家） |
| MoE | Fused MoE kernel，DeepSeek-V3/Llama-4/standard top-k routing，**FP8/FP4 量化专家** |
| Sampling | sorting-free Top-K/Top-P/Min-P、Speculative Decoding（chain） |
| Communication | AllReduce、MNNVL、NVSHMEM |
| Other | RoPE（LLaMA 3.1）、RMSNorm/LayerNorm/Gemma fused、SiLU/GELU fused gating |

CUDAGraph + torch.compile 兼容，SM75–Blackwell。

> **给 KernelAgent 的建议**：上表中的算子（MLA、FP4 GEMM、Fused MoE、Paged KV、POD-attention、Speculative Decoding）**不要从头手写**——FlashInfer 已是 SOTA。若要切入，只能做"特定 shape/精度组合下 FlashInfer 未覆盖的变体"或"集成层面的调度优化"。

### 3.2 【实时核实】MLA + Matrix Absorption（DeepSeek）

- **算子**：Multi-head Latent Attention，把 K/V 压到低秩 latent 空间；decode 时用 matrix absorption 把 W_K/W_V 吸收进 W_q/W_o，KV cache 只存压缩 latent（DeepSeek-V2/V3 d_c=512 + d_r=64 共享 RoPE key/token），128K+ 长上下文显存降约一个数量级，推理 ~5x。
- **复杂度**：decode 从 memory-bound（读全 KV）大幅缓解；但上投影 GEMM（M=1, K=d_c, N=n_h×d_h）算术强度极低，是 MLA decode 的关键瓶颈。
- **为何复杂**：RoPE 与低秩压缩不兼容（RoPE 插在 W_Q 与 c_KV 之间破坏可吸收性）→ 用**解耦 RoPE**：低秩部分按无 RoPE 吸收，RoPE 部分单独算并存共享 k_R；输出是 `[吸收支 || RoPE 支]` 两分支拼接，head_dim 不一致，kernel 需处理非对齐维度。
- **成熟度**【实时核实】：DeepSeek **FlashMLA**（Hopper 专用 CUDA）、FlashInfer/vLLM MLA backend、TensorRT-LLM xQA 均已实现 absorbed-matrix decode kernel。
- **优化空间**：小——已被吃透。增量：FP8 latent cache + 吸收矩阵 groupwise scale、上投影 GEMM 与 attention 融合。

### 3.3 【实时核实】FlashAttention-3

- **来源**：arxiv 2407.08608（Tri Dao + Meta + NVIDIA）。
- **技术**：Hopper 上异步 TMA + warp-specialization（producer/consumer ping-pong）+ WGMMA + block softmax 交织；FP8 用 incoherent processing（random Hadamard）降 2.6x 误差。
- **性能**：H100 FP16/BF16 fwd+bwd 740 TFLOPs（75%），FP8 fwd ~1.2 PFLOPs。
- **成熟度**：闭源 CUDA 极致，Triton 难超 70-80%。**不要手写通用 FA-3；但视频扩散的 STA/SSTA 是 FA-3 未覆盖的稀疏变体，有空间。**

### 3.4 【实时核实】DeepSeek-V3 关键算子

- **架构**：671B MoE / 37B 激活；auxiliary-loss-free 负载均衡；MTP（多 token 预测，第二 token 接受率 85-90%，推理 ~1.8x）。
- **FP8 训练**【实时核实】：**首个极大规模 FP8 混合精度训练**，正反向均 E4M3 + per-group scaling，绕过 TE 默认方案。
- **W4A8 dequant-fused GEMM**：FP4 存权重 + FP8 激活，2x4 block scale（比 NVFP4 16-block 更细）。
- **DeepGEMM**【实时核实，github deepseek-ai/DeepGEMM】：DeepSeek 开源，JIT 编译的 FP8/FP4/BF16 GEMM + Fused MoE（Mega MoE，计算通信重叠）+ MQA scoring，核心代码轻量，H800 上 1350+ FP8 TFLOPS（比 CUTLASS 3.6 快 ~2.7x），性能匹配/超过专家级库；**官方定位为"学习 NVIDIA GPU kernel 优化的简洁资源"**——是 FP8 GEMM/MoE 的极佳 SOTA 参照与学习样本（2026-04 更新含 Mega MoE / FP8xFP4 / FP4 Indexer）。对 KernelAgent 而言：FP8/FP4 GEMM 已有开源 SOTA，手写超越难度大，但可作为对齐基准。
- **DualPipe**：把 MoE dispatch/all-to-all 与前层 MLP 计算重叠，"白嫖"通信时间。
- **优化空间**：FP8/FP4 GEMM 已有 DeepGEMM/CUTLASS 开源 SOTA（Triton 对 FP4 原生指令暴露不完整，主要跟 CUTLASS 路线）；MoE EP all-to-all 的 fused permute/sort 可 Triton，但 all-to-all 走 NCCL。

### 3.5 【综述】PagedAttention / Paged KV Cache（推理 decode 核心瓶颈）

- **算子**：KV cache 按 block 分页 + block table 间接寻址 + attention 内部按 block table 读非连续 KV。
- **复杂度**：decode memory-bound（每 token 读整 KV cache），分页消除碎片可多塞 2-4x 并发。
- **成熟度**：vLLM PagedAttention、SGLang RadixAttention、FlashInfer Cascade、FA-3 原生支持 paged KV block table。
- **优化空间**：小。增量——block size 调优、KV 量化（FP8/INT4）与 paged 融合、GQA-aware 布局。

### 3.6 【综述】Speculative Decoding / Tree Attention / MTP

- **算子**：speculative decoding（EAGLE/Medusa）一次 verify 多个 draft token；tree attention 用 varlen 一次算树形多候选；MTP（DeepSeek-V3）延迟一步预测多 token。
- **复杂度**：变长、树形结构、不规则。
- **成熟度**：FlashInfer 已支持 chain speculative sampling；vLLM/SGLang 支持树形。Triton 可写 tree attention（varlen FA 变体）。

### 3.7 【综述】MoE Grouped GEMM + EP All-to-All

- **算子**：router top-k → token permute by expert → all-to-all dispatch → grouped GEMM（每专家一组）→ all-to-all combine → unpermute → 加权求和。
- **复杂度**：动态 shape（每专家 token 数动态）、负载不均、all-to-all 通信 bound。
- **成熟度**：FlashInfer Fused MoE（FP8/FP4 量化专家）、Megatron MoEAlltoAllTokenDispatcher、Tutel。
- **优化空间**：fused permute+sort+memcpy 可 Triton；all-to-all 走 NCCL；动态 padding 到 power-of-2 静态化便于 autotune；DeepSeek DualPipe 把 dispatch 与前层 MLP 计算 overlap。

### 3.8 【综述】RoPE 变体 / Varlen Attention / SwiGLU+RMSNorm 融合

- **RoPE**（YaRN/NTK/LLaMA-style/3D）：Liger-Kernel 已有开源 Triton【实时核实】，fold 进 QK^T prologue 是 SOTA。
- **Varlen/Packed Attention**（cu_seqlens）：FA varlen 标配，训练 packing 必用，Triton 教程完整但落后官方 ~30%。
- **SwiGLU+RMSNorm+Residual**：Liger-Kernel【实时核实】已有 RMSNorm/RoPE/SwiGLU 等开源 Triton（训练 +20%/-60%）。**不该重造。**

### 3.9 【实时核实+综述】KV Cache 压缩 / Decode 加速 / 投机解码（长上下文显存墙的突破口）

> 这一节是 LLM serving 的"长上下文"专属战场，prefill vs decode 二分法在此最明显：decode 是 memory-bound，KV 读取是主成本。

- **OSCAR 2-bit attention-aware KV 量化**【实时核实，arxiv 2605.17757】：离线谱协方差感知旋转 `R = U·Hadamard·bit-reversal`，2.28 effective bits 接近 BF16，比 3-bit TurboQuant 高 ~40 分；key 用 `Q^T Q` 协方差、value 用 `V^T S^T S V` score-weighted 协方差做 attention-aware 校准。**长上下文显存 ~8x 压缩，是真蓝海候选**（反量化融合进 decode attention kernel 可 Triton，但旋转校准需离线流程）。
- **FlashDecoding（split-K decode）**：把 KV cache 沿 L 维切分给多 SM 并行，再 all-reduce partial softmax——长 context decode 的 SOTA 思路，Triton 可写。
- **Tree Attention / EAGLE-2 动态树 / MTP verify**【综述】：投机解码验证阶段，一次 verify 多个 draft token。难点：动态树形（shape 完全动态，CUDA Graph 难 capture）、非平凡稀疏树形 mask、KV slot 分配/回滚。FlashInfer 用 BSR 块稀疏统一表达。EAGLE-2 ~4-5x、Medusa ~2.3-3.6x、MTP ~1.8x。Triton 可实现 tree attention，SOTA 需 JIT。
- **Mooncake / SGLang HiCache**【综述】：KV cache 中心化——Mooncake 全局 KV 池零拷贝复用；SGLang HiCache 多级缓存（GPU→CPU→远端）+ 流水线异步预取。系统级优化，非单算子。
- **Chunked Prefill + 混合 batch**【综述】：把长 prompt 切 chunk 与 decode 同 batch，避免生成停顿。难点：prefill（compute-bound）与 decode（memory-bound）混合负载 kernel 难同时最优 + 动态 shape。FlashInfer BSR 统一抽象是底层支撑。
- **CUDA Graph + 间接 buffer**【综述】：decode 每步数十 kernel，launch overhead 占 30-50%；CUDA Graph 录图 replay，动态 shape 用 slot_mapping 间接 buffer 更新。**底层 kernel 必须 graph-friendly（无 CPU 同步、无条件分支）**——这是对任何手写 decode kernel 的硬约束。

> **给 KernelAgent 的提示**：长上下文 serving 的算子大多已被 vLLM/FlashInfer/SGLang 吃透（PagedAttention、FlashDecoding、tree attention、CUDA Graph）。**唯一有手写空间的是 OSCAR 类 attention-aware KV 量化的"反量化融合进 decode attention"**——但需配合离线旋转校准，且 SOTA 仍在演进。

## 四、具身 / 3D / 机器人世界模型算子（蓝海）

> 这一领域**库散落、未统一到 Triton**，是真正的优化蓝海。来源：具身3D 调研 subagent（结构完整，6 字段，含训练 vs 部署区分）。

### 4.1 ★ 3DGS 可微光栅化（前向 + 反向）

- **出现位置**：3D Gaussian Splatting（SIGGRAPH 2023）核心；4DGS、GS-SLAM、机器人场景回放。
- **复杂度**：百万级高斯 × 1080p-4K；前向偏 memory-bound（tile 内 alpha blending）；**反向显存峰值极高**（需保存或重放每像素中间态 transmittance）。
- **为何难优化**：动态每 tile/每像素命中数 → warp 分支发散；反向需重放前向遍历顺序（recompute 抉择）；投影+2D 协方差+SH 求值是一串小核；全局 radix sort；反向梯度原子 scatter-add。
- **主流实现**：原版 INRIA CUDA、gsplat（nerfstudio，batched/fused 变体，社区优化参考）。**反向未 Triton 化**【综述+需核实】。
- **优化空间**：fused 前向+反向 Triton 端口、反向重算替代存储、近似/层级排序、fp16、fused projection+SH+2D-cov。
- **Triton 可行性**：前向高，反向中。**综合价值排名第 1**（FLOP 大 + 实时渲染/机器人回放延迟敏感 + gsplat 反向未 Triton 化）。
- **训练时**：反向显存是主瓶颈。**部署时**：4K@30-60Hz 实时渲染，只跑前向，fused + 量化是关键。

### 4.2 ★ 稀疏 3D 卷积（spconv / MinkowskiEngine）

- **出现位置**：Occupancy 预测、LiDAR 检测、BEV backbone、机器人 3D 场景理解。仅 active voxel 计算卷积。
- **复杂度**：active 体素 50K-500K，隐式 GEMM 可吃满 tensor core，compute-bound；rule book 每层重建显存可达 GB。
- **为何难优化**：hash 表 + rule book 两阶段（前者不规则访问）；gather/scatter 不规则；dynamic batch；submanifold vs regular 分别处理；反向需稀疏梯度。
- **主流实现**：spconv 2.x（工业主流）、MinkowskiEngine、TorchSparse。**无成熟 Triton 端口**。
- **优化空间**：implicit GEMM Triton、fused hash+rule gen、混合 dense/sparse。
- **Triton 可行性**：implicit GEMM 部分高，hash/rule book 部分中-难。**综合价值排名第 2**（自动驾驶 50Hz 实时性高 + 无 Triton 端口）。

### 4.3 ★ 点云预处理（Voxelization / FPS / Ball Query / KNN）

- **出现位置**：PointNet++/PVCNN/CenterPoint/机器人点云全栈。
- **复杂度**：voxelization scatter-add memory-bound；FPS 串行 O(N·K) launch-bound。
- **为何难优化**：不规则 scatter（atomic）、hash 冲突、动态点数；FPS 串行依赖难并行。
- **主流实现**：CUDA 算子散落（mmcv/spconv/cumm/cuML）。
- **优化空间**：fused hash+pool Triton（voxelization 可行性高）、grid-based O(1) 邻居替代 ball query、并行 FPS 近似。
- **Triton 可行性**：voxelization 高，FPS 中（需算法改造）。**综合价值第 3-4**（LiDAR/机器人 10-30Hz）。

### 4.4 ★ BEV Lift-Splat（外积 + scatter-add）

- **出现位置**：LSS/BEVFusion/BEVDet，6 相机 → BEV 网格。
- **复杂度**：外积中间张量爆炸（C×D×H×W 数十 GB，显存峰值高）；scatter-add memory-bound + atomic。
- **为何难优化**：必须 fused 不物化外积；不规则 scatter + 双线性插值；每相机内外参不同。
- **主流实现**：mmdetection3d CUDA voxelpool、TensorRT plugin。
- **优化空间**：fused lift-splat（逐像素累加到 BEV）、fp16 scatter、warp reduce。**Triton 可行性高**。

### 4.5 【综述】点云 Transformer Attention（PCT / Point-MAE / PTv3）

- PTv3 的"序列化（Z-order/Hilbert）+ window attention"把不规则点集规则化以复用 FlashAttention——是关键思路。序列化后等价 1D window attention，Triton 可写。

### 4.6 【综述】RSSM（DreamerV3 世界模型）

- GRU + posterior/prior + KL balancing，循环依赖不可并行，kernel launch overhead 主导。JAX jit+vmap 是官方 SOTA（跑 4096 env）；PyTorch 版用 torch.compile + CUDA Graphs + fused RSSM cell。

### 4.7 【综述】可微物理 / 并行 Env Rollout

- MuJoCo MJX（JAX）、Brax、Genesis（Taichi）、NVIDIA Warp、Isaac Lab。批量刚体动力学 + 接触求解，分支 + 稀疏雅可比难静态图编译。CUDA Graphs 捕获整 env step 是 Isaac Lab 主路径。Triton 化可行性低（更适合 Warp/Taichi/JAX）。

### 4.8 【综述】Diffusion/Flow Matching Policy 去噪（π0/RDT）

- 动作维度小，去噪网络 launch-overhead-bound 而非 compute-bound。瓶颈在 conditioning 编码器（预计算缓存）+ 少步 flow matching + CUDA Graphs 捕获去噪循环。实时控制（50-1000Hz）延迟极敏感。

### 4.9 【综述】VLA 多模态 Attention（GR00T / π0 / OpenVLA）

- 图像 token + 文本 token + 动作 token，compute-bound，FA-3 + token 压缩 + KV 量化 + vLLM 部署。成熟度高，增量优化。

## 五、大模型训练系统算子

> 来源：训练/低比特/通信融合 subagent（16 算子，6 字段，训练 vs 推理区分表）。**训练侧已被 TE/CUTLASS/FSDP2/Liger 高度吃透，手写空间集中在新精度（FP4）与通信融合。**

### 5.1 【综述+实时核实】FP8 Fused GEMM（+activation+norm epilogue）

- **成熟库**：NVIDIA Transformer Engine（te.Linear/RMSNormLinear，delayed scaling+amax history）、CUTLASS 3.x（epilogue fusion+stream-K）、cuBLASLt。DeepSeek-V3 自研正反向 E4M3 + per-group scaling。
- **优化空间**：per-tile/per-block scale、amax 平滑、epilogue 融合（RMSNorm+residual+RoPE 塞进 GEMM epilogue）、反向 dequant 融合。Triton 中等（per-tile scale + tl.dot fp8）。

### 5.2 【综述+实时核实】FP4 / MXFP4 / NVFP4 GEMM（W4A8 dequant-fused）

- **成熟库**：CUTLASS 3.5+/Cute（MXFP4/NVFP4 双 scale）、TensorRT-LLM、DeepSeek-V3 自研 2x4 block scale、FlashInfer FP4 GEMM。
- **优化空间**：per-channel vs 2x4 block scale、scale 预取 + async TMA、stochastic rounding、online quantize。**Triton 对 FP4 原生指令暴露不完整，主要靠 CUTLASS/CUDA**——KernelAgent 若切入需跟 CUTLASS 路线。
- **意义**：Blackwell 时代核心，影响超长上下文 + 超大 MoE 可部署性。

### 5.3 【综述】ZeRO/FSDP 通信-计算融合（all-gather+forward / reduce-scatter+backward）

- **复杂度**：通信 bound，万卡训练占 20-40% step time。
- **成熟库**：PyTorch FSDP2 + DTensor（layer-aligned bucketing）、DeepSpeed ZeRO-3、Megatron distributed optimizer。
- **优化空间**：all-gather/reduce-scatter 与 GEMM overlap（双 stream + event）、FP8 流式聚合（省 2x 通信量）。**Triton 难切入通信侧**（NCCL 主导），但 fused dequant+GEMM prologue 可做。

### 5.4 【综述】MoE EP All-to-All Dispatch/Combine

- **复杂度**：动态 shape、负载不均、all-to-all 通信 bound。
- **成熟库**：Megatron、Tutel、FlashInfer Fused MoE、DeepSeek DualPipe。
- **优化空间**：fused permute+sort+memcpy（Triton 可）、动态 padding 静态化、dispatch 与前层计算 overlap。**all-to-all 仍走 NCCL**。

### 5.5 【综述】Gradient Checkpointing + Fused Recompute

- selective recompute（只重算 attention，算力 +5-10%，显存 -50%）；fused recompute kernel（FA 已天然不存 S/P）。Triton 友好。

### 5.6 【综述+实时核实】Fused AdamW / ZeRO Optimizer Step

- PyTorch `fused=True`、Apex FusedAdam、DeepSpeed。**Triton 可超 PyTorch foreach**，elementwise 教科书场景。

### 5.7 【综述+实时核实】SwiGLU+RMSNorm+Residual / RoPE / Activation 量化

- **Liger-Kernel 已开源**【实时核实】：RMSNorm/RoPE/SwiGLU/CE/FusedLinearCE/GeGLU/LayerNorm，训练 +20%/-60%，支持 Ascend。**不该重造**——直接用或在其基础上针对特定模型微调。

### 5.8 【综述】Ring Attention / Context Parallel

- 长上下文训练核心。通信+计算 overlap、Striped Attention 均衡负载、KV async TMA。Triton 写 attention 块可行，P2P 走 NCCL。

### 第一梯队（最值得 KernelAgent 投入）

1. **STA / SSTA**：视频扩散 85% 时间在 attention，STA/SSTA 是 2025 最新开源方向，Triton 可写、有开源参照、演进中——**综合价值最高**。建议：Triton 实现不同 tile 形状/stride/selective 策略，benchmark vs FastVideo 原版。
2. **3D-RoPE + attention 融合**：所有视频 DiT（HunyuanVideo/Wan/CogVideoX）必用，当前无成熟开源 Triton 融合 kernel，融合消除中间物化 + 省一次 HBM 往返；**单卡可验证、baseline 是 eager RoPE+FA2、覆盖最广**——是最稳的"快速且高价值"切入点。
3. **3D VAE causal Conv3d + GroupNorm+SiLU 融合（+反卷积）**：causal 约束让 cuDNN 失效，专属 Triton kernel 收益确定；解码是推理最后一步，用户感知延迟最直接；无成熟 Triton 实现。
4. **3DGS 可微光栅化（反向）**：FLOP/显存密集、实时渲染延迟敏感、gsplat 反向未 Triton 化——典型"memory-bound + 有明确手写空间"。
5. **SageAttention + STA 融合**：把低比特量化与稀疏滑动窗口融合，是 FlashInfer/FA-3 未覆盖的交叉空白。
6. **稀疏 3D 卷积 + 点云预处理 + BEV splat**：具身/自动驾驶蓝海，无 Triton 端口，scatter-add/implicit GEMM 模式清晰。

### 第二梯队（Triton 易切入，但库较成熟）

5. FP4 GEMM（跟 CUTLASS）、3D-RoPE 融合、3D VAE 融合、Patchify fused、MoE fused dispatch、Fused AdamW、fused recompute。

### 不建议手写（已吃透）

6. 通用 FA-3、MLA/Paged KV/FP8 GEMM、RoPE/RMSNorm/SwiGLU（Liger 已有）——直接用成熟库或做集成调度。

## 八、给 KernelAgent 的下一步建议

结合本仓库已有的 RMSNorm 优化闭环经验（本机 LLM 生成 + 云端 GPU 真跑真测，见 `docs/RMSNorm优化实录.md`）：

1. **首选（快速且高价值）：3D-RoPE + attention 融合**：
   - 所有视频 DiT 必用、当前无成熟开源 Triton 融合 kernel、单卡可验证、baseline 是 eager RoPE + FA2、覆盖模型最广（HunyuanVideo/Wan/CogVideoX）。
   - 与 RMSNorm 同属"memory-bound + 融合能拉开差距"类型，闭环方法论可直接迁移。
   - 可复用 `examples/optimize_rmsnorm_remote.py` 的驱动模式，problem 换成"3D-RoPE 融合 attention"，shape 用 HunyuanVideo 真实配置。

2. **次选（综合价值最高）：STA / SSTA**：
   - 视频 DiT 85% 时间在 attention，STA 比 FA3 快 1.6-10x，2025 最新开源（FastVideo）、Triton 可写、演进中。
   - 优化点：tile 形状（T×H×W）、stride、selective 策略、与 3D-RoPE 融合、反向 fused。基线 = FastVideo 原版 STA。

3. **三选（收益确定）：3D VAE causal Conv3d + GroupNorm+SiLU 融合**：
   - causal 约束让 cuDNN 失效，专属 Triton kernel 收益确定；解码是用户感知延迟最直接的环节；单卡推理可验证。

4. **四选（快速胜利）：Sandwich-LN + AdaLN 融合**（CogVideoX）：
   - LN 融合是 Triton 教科书场景，实现门槛低，每 block 省 3-4 次 HBM 往返，适合积累优化数据。

5. **避开**：通用 FlashAttention-3、MLA、FP8 GEMM、Paged KV、RoPE/RMSNorm/SwiGLU（1D）——FlashInfer/FA-3/TE/DeepGEMM/Liger 已吃透，手写难超越，ROI 低。可作为 SOTA 对齐基准（尤其 DeepGEMM，官方定位"学习 GPU kernel 优化的简洁资源"）。

4. **环境注意**：调研与 baseline 复现都依赖网络抓取 arxiv/GitHub；本机走代理 13363（`curl -x http://127.0.0.1:13363` 或 `http_proxy/https_proxy` 环境变量）。WebFetch 工具在本环境被域名策略阻断，用 curl 通道更可靠。
